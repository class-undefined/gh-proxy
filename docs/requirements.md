# Git 访问网关需求规格

## 1. 背景与范围

内网用户需要通过统一入口访问 GitHub 等 Git 托管平台，完成代码拉取、推送和版本发布。现有 HTTP 代理无法直接承载 SSH 协议，也不能完整覆盖平台 API 与 Release 附件传输。

建设独立网关，统一提供 Git HTTP(S)、SSH 和平台 API 的访问能力，并支持经现有上游代理出站。实现语言为 Rust；首期支持 GitHub，为其他平台预留适配接口。

## 2. 建设目标

1. 支持 GitHub，预留其他 Git 平台扩展能力。
2. 支持 Git HTTP(S) 和 SSH。
3. 尽量保留客户端原生仓库地址和操作习惯。
4. SSH 保持端到端认证，由远端平台验证客户端已有公钥。
5. 支持仓库读写、tag 推送及 Release 等平台操作。
6. 按协议可见范围限制客户端、平台、仓库和操作。
7. 使用标准代理环境变量连接上游。
8. 支持服务管理、状态检查和必要日志。

## 3. Git 操作

| 操作 | 说明 |
| --- | --- |
| clone | 克隆仓库 |
| fetch、pull | 获取远端更新 |
| push | 推送分支或其他 Git 引用 |
| tag 推送 | 推送本地 tag |
| commit | 客户端本地操作，无需网关参与 |

HTTP(S) 与 SSH 均应覆盖正常 Git 数据传输。访问权限由网关策略和远端平台共同约束；SSH 仓库级权限的边界见下文。

## 4. HTTP(S) 入口

提供 Git HTTP(S) 反向代理，路径尽量与原生仓库路径一致：

```text
https://<网关地址>/owner/repo.git
```

客户端可通过 Git URL 改写继续使用原有地址。网关应识别平台、仓库及 Git 操作，并支持配置：

- 客户端来源范围；
- 仓库白名单；
- 只读或读写权限。

涉及 Token 等凭据时，客户端到网关必须使用 HTTPS。TLS 终止方式在部署阶段确定。

## 5. SSH 入口

提供受限 SOCKS 代理，透明转发端到端 SSH 连接。客户端配置示例：

```sshconfig
Host github.com
    User git
    ProxyCommand connect-proxy -S <网关地址>:<SOCKS端口> %h %p
```

配置后继续使用原生地址：

```sh
git clone git@github.com:owner/repo.git
git push
```

网关必须限制客户端来源、目标域名和端口，避免成为通用代理。远端平台直接验证客户端已有公钥。

透明转发无法识别加密连接中的仓库和 Git 操作，不能强制执行 SSH 仓库级白名单或只读策略。SSH 仓库访问权限由远端平台根据用户公钥决定。

如果要求网关检查 SSH 仓库路径，需要终止 SSH 并使用网关上游身份，届时不再满足由平台直接验证客户端原有公钥的要求。这属于另一种架构，不在当前透明代理方案中混用。

## 6. 平台 API 与 Release

Release 创建、更新、附件上传与下载属于平台 API 操作，不能仅通过 Git 协议完成。

网关应支持：

- 按仓库白名单控制 API 请求；
- 按策略允许查询、创建、更新等操作；
- 支持 Release 附件上传、下载；
- 校验附件域名与每一次 HTTP 重定向的目标；
- 首期接入 GitHub，再按需增加平台适配器。

必须校验目标路径及重定向目标，防止访问未授权地址。对附件直链的授权归属和路径校验见架构文档，不应仅凭附件域名允许任意下载。

## 7. 上游代理

```dotenv
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
ALL_PROXY=socks5h://127.0.0.1:7891
NO_PROXY=localhost,127.0.0.1
```

流量路径：客户端 → Git 访问网关 → 可选上游代理 → Git 平台。

- Git HTTP(S) 与平台 API 出站遵循 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`。
- SSH 透明转发支持使用 `ALL_PROXY` 配置 SOCKS 上游。
- 支持常见大小写变量形式，明确冲突时的优先级。
- 明确 SOCKS DNS 解析位置，`socks5h` 表示由代理端解析。
- 无上游配置时，可选择直连或拒绝出站。
- 上游代理不可用时不得静默绕过代理直连。
- 日志、错误、状态信息不得暴露代理 URL 中的凭据。

环境变量的具体优先级及直连例外语义由架构文档规定，并在实施时验证。

## 8. 运维与保密

支持启动、停止、重启、配置生效验证、健康或就绪检查和必要审计日志。日志不得包含 Token、认证头、代理凭据或带凭据的 URL。

## 9. 实施前待确认

- 首批客户端 CIDR、仓库白名单、各仓库读写权限和 Release 操作范围。
- 接受 SSH 仓库授权由远端平台控制，网关只控制来源与目标。
- 网关域名、TLS 终止方式、监听地址、部署方式。
- 上游代理实际地址、无上游时的出站模式及明确允许的直连例外。

用户尚未提供这些部署值；文档中的占位符不是可用于生产的授权配置。
